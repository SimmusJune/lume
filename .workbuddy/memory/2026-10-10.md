## 新增 Smart Review 播放模式（间隔重复 / 艾宾浩斯）

需求：给孩子做的英语儿歌熏听，想加一个基于「艾宾浩斯遗忘曲线 → 间隔重复」的播放模式来强化记忆。

### 先厘清的概念（决定了怎么设计）

艾宾浩斯遗忘曲线是**现象**，间隔重复是**方法**；真正让间隔重复生效的是「时间间隔 + 主动回忆」两根支柱。熏听没有主动回忆这一环，所以只能解决两件具体的事：新歌只听过一遍之后好几天不再出现；或者一首歌连放十遍把孩子听腻。设计上拆成**两层**：

1. **跨天（Leitner 简化档位）**：每首歌记 box / 到期时间，完整听完升档、中途切走退档，下次打开优先排今天到期的。
2. **会话内（递进间隔）**：一次播放里让待强化的歌出现 2~3 次，中间隔开若干首其他歌且间隔逐步拉长。

用户拍板「两层都做」，UI 命名 **Smart Review**（沿用工程里档位标签的英文风格：Repeat All / Repeat One / Shuffle / Smart Review）。

  - `ReviewSnapshot{states:[String:ReviewState]}`：同样手写 `init(from:)` + `nonisolated var normalized`。
  - `ReviewIntervals.days = [1,2,4,8,16,30]`、`maxBox = 5`、`interval(forBox:)`。
  - `SpacedRepetitionStorage`：**`nonisolated`** 静态成员、单个 UserDefaults key `lume.review.states`（整包 JSON 编码）。
  - `SpacedRepetitionStore`（`@MainActor ObservableObject`，`shared`）：`state(for:)` / `isDue` / `dueCount` / `recordCompleted` / `recordSkipped` / `clearAll` / `reloadFromStorage` / `importSnapshot`。写入时上限 2000 条按 lastReviewedAt 淘汰。

### 踩坑

- 排程器第一版的「补位轮」有**级联 bug**：主线走完后循环 `for song in spine` 补位，而每次补位本身又会触发更多已登记的重复项，4 首的池子跑出 18 首、单曲出现 5 次。改成「自适应间隔 + 有界队尾补齐 + 补齐不再登记」后收敛。**池子越小，单曲实际重复次数会被压缩**（2 首池 a b a；1 首池只有 1 次），这是刻意的取舍。
- 断言「隔 N 首」时别用数组下标差。同一位置会夹着别的歌的重复项，下标差会偏大。要数**两次出现之间有几首「首次出现」的歌**。
