## 随机播放重做 + 修两处定位失效（PlayerViewModel / ExploreView）

- 背景：原随机是「每次现场抽 index、只排除当前下标」的随机跳转，不保证一轮内不重复；且 `currentIndex` 是独立存储的下标，队列重建/删歌后会与当前曲错位。
- `Lume/ViewModels/PlayerViewModel.swift`
  - `currentIndex` 由存储属性改为 **计算属性**（`playlist.firstIndex(of: currentMediaID)`），删掉所有手写下标的地方（setQueue / playFromQueue / previousTrack / advanceTrack / removeFromQueue / nextTrackIDAfterDeletingCurrent / clearPlaybackState）。
  - 随机播放改为「**每轮洗牌成一个排列**」：新增 `shuffleRemaining`（本轮剩余）+ `shufflePoolSignature`（队列快照）。抽空才 `playlist.shuffled()` 重洗；池子从末尾取，若新一轮第一首 == 刚播完那首就随机换位，避免跨轮连续重复。
  - `resetShufflePool()`：`setQueue` 里判定 `isNewSession`（队列或起点曲变化）时调用，`clearPlaybackState()` 也调用。
  - 顺序播放里当前曲不在队列时兜底回 `playlist[0]`。
  - `removeFromQueue(id:nextID:)` 简化为 `removeFromQueue(id:)`。
- `Lume/Views/ExploreView.swift`：`play(item:)` 去掉 `if origin != .library` 分支，**无条件 `setQueue`**（队列为空用 `[item.id]`，队列里没有该曲则插到首位）。
- 验证：抽出等价模型用 `swiftc` 编译实跑 —— 200 次推进 / 40 轮，每轮恰好 5 首不重复、跨轮无连续重复、各曲出现次数 40~41（均匀）。**注意第一版「重洗时排除当前曲」的写法有 bug**：会导致后续每轮只有 N-1 首、被排除那首整轮缺席，已改成整队列 `shuffled()` + 首尾换位。

## 环境备忘

- 本机 `xcodebuild` 无法完成完整编译：`swift-plugin-server produced malformed response`，所有 `@State` / `#Preview` 宏展开失败（开沙箱关沙箱都一样），属 Xcode 环境问题，不是代码问题。该失败**偶发**：同一条 `swiftc -typecheck` 有时通过、有时报 100+ 条宏错误，别被一次通过骗到，判断前先看错误里有没有 `external macro implementation type`。
- 判断技巧：`grep 'error:' log | grep -v 'external macro implementation type'` 剩下的才是真实错误；`cannot assign to property: 'self' is immutable` / `cannot find '$xxx' in scope` 都是 `@State` 宏没展开的连带错误，不是代码问题。
- 验证 Swift 改动改用「抽取等价片段 + `swiftc -typecheck` / 直接编译运行」的方式；不带宏的 ViewModel/Service 层可以直接 `swiftc -typecheck -sdk $(xcrun --sdk iphonesimulator --show-sdk-path) -target arm64-apple-ios17.0-simulator <files>` 真编译。
- 注意：命令管道到 `head` 时 `$?` 是 `head` 的退出码，会掩盖编译失败 —— 一定要用 `; echo exit=$?` 或写日志后 grep。
- 构建时不要用默认 DerivedData（沙箱会拒绝写入），如需可加 `-derivedDataPath ./.build-dd`，用完记得删除。
